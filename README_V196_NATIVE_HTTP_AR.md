# توافق جلب وتشغيل القنوات داخل العطا — 1.0.196

فُحص ملف YTV PRO المرفق محليًا، ببصمة SHA-256 `ca7ea4e9fa08c60fd6e1ffae65fc15c08ed72f2dbd6e14d4f5ff70b0bcd041af`، دون تشغيله أو إجراء طلبات إلى المصدر. واجهة قوائم ياسين تطلب `categories` ثم `categories/{id}/channels`. واجهة YTV PRO تطلب `channel/{id}`، وتهيئة `config/player`، ثم تمرر بيانات Stream إلى المشغّل. تحويل رد API موجود في المعترض `xb/g` ويستخدم ترويسة الرد `t`؛ لا تُنشر أي قيم مفاتيح.

تأكد من مسار `PlayerActivity.R` أن المشغّل يقرأ الترويسات وUser-Agent، ويستخدم عند غياب الأخير قيمة متصفح افتراضية محددة في المنشئ. يستعمل مصنع اتصال أندرويد المباشر بمهل اتصال وقراءة 8000 مللي ثانية، ثم يختار HLS/DASH أو صيغة أخرى من الرابط. مسار معالجة الرابط الإضافية مشروط بـ`urlType == 2`؛ لا يثبت وجوده وحده أن روابط نتيجة المالك تحتاج هذه المعالجة. لا تُنسخ خوارزمية خاصة أو تُستخرج مفاتيح أو تُولّد توقيعات.

كان العطا يترك المصدر ذي الترويسات الفارغة لاستخدام User-Agent الافتراضي لـOkHttp. يطابق الاختبار الداخلي الآن إعداد المتصفح الافتراضي عند غياب قيمة مقدمة، ويحافظ على القيم الصريحة، ويستخدم DefaultHttpDataSource الخاص بأندرويد بمهل 8 ثوانٍ. تسري الإعدادات على مسار اختبار القنوات الداخلي فقط عبر نقطة حقن النقل الموجودة في المشغّل نفسه؛ لا يُضاف مشغّل مكرر. تبقى بيانات التشغيل من المصدر عبر Worker، ثم يحمل الهاتف الوسائط مباشرة؛ لا يوجد إثبات أن روابط المصدر مرتبطة بعنوان IP أو أن فرق النقل سبب فشل الهاتف.

كذلك تحتفظ النافذة بجلسة واحدة ومصادر ثابتة وساعة واحدة عند الانتقال بين البدائل. تُتجاهل إشعارات المحاولات المنتهية، ويُمنع تكرار حالات المشغّل المتطابقة. تبقى إضافة 1.0.195 الخاصة بسبب الإغلاق ونسخ آخر تقرير في صفحة القنوات. التقرير `native-channel-3` يضيف أسباب أخطاء تحميل ثابتة مثل DNS وTLS وTIMEOUT وHTTP_STATUS وPARSER، وحجم البيانات ومدة التحميل، دون نص الاستثناء أو الروابط أو قيم الترويسات أو محتوى الرد.

تختبر الوحدة النقل إلى خادم محلي تجريبي فقط: User-Agent الافتراضي والصريح، وReferer، وبقاء المسار والاستعلام كما هما، وتسجيل HTTP 403 دون بيانات حساسة. وتختبر اتساق الوقت وتثبيت المصادر والإشعارات القديمة. اختبار الجهاز يشغّل Media3 مع قراءة متوقفة تجريبية دون شبكة، ويتحقق من بقاء نفس نافذة الفيديو عبر مصدرين، ومن الاحتفاظ بالتقرير بعد الرجوع. نجاح الفحوص لا يثبت تشغيل البث الحقيقي؛ يحتاج ذلك تجربة المالك.
