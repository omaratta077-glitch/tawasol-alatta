# مراجعة الموقع ومطابقته للتطبيق — Web 14.0

النطاق: موقع Cloudflare الموجود في المستودع؛ التطبيق هو المرجع. لا تغيير في android-native أو رقم APK أو التوقيع. البداية من main عند 94c6d0d.

## أعطال مؤكدة ومعالجتها

- ثلاث طبقات inline لتكبير الموبايل وتجاوزات html.mobile-device في CSS كانت تتنافس مع مقاسات الواجهة الأحدث. أزيلت قواعد التكبير القديمة؛ ملف native-parity.css مسؤول عن مقاسات واجهة الموقع لجميع الشاشات، مع الإبقاء على أنماط المشغلات والمكالمات القائمة.
- أزرار جانبية بلا data-page كانت تمرر undefined إلى showPage ثم تنهار محاولة classList. التحقق من الوجهة يسبق تغيير الصفحة، و«المزيد» يفتح قائمة فعلية.
- فشل أي شبكة عند استرجاع الجلسة كان يمسح الحساب المحفوظ. تم الاحتفاظ بالجلسة عند تعثر الشبكة، ومسحها فقط عند HTTP 401/403 من فحص الحساب. إعادة GET واحدة ضمن مهلة كلية 20 ثانية، وطلبات الكتابة لا تتكرر.
- معلومات الملف كانت تجلب عند بدء الرئيسية رغم عدم عرض الملف؛ أزيل الطلب الزائد. خطأ تحميل المنشورات يظهر معه زر إعادة المحاولة.
- بطاقات الاقتراحات تستخدم أزرارًا غير مضبوطة المظهر؛ صارت بخلفية داكنة ونص وحقول وأحجام صور محددة. الصور الافتراضية سوداء وذهبية مع ترميز محرف الاسم.

## مرجع التصميم

PremiumChrome.kt وملفات atta_ic_*.xml كما هي. 52 أيقونة من نفس pathData، والترويسة 62px، والشريط 74px مع مساحة أمان النظام، والبطاقات 66px. ترتيب RTL: الرئيسية، الرسائل، الملف، القرآن، الأحاديث، الأذكار، الرياضة، يوتيوب، المزيد. الأصدقاء والبحث والإشعارات في الأعلى وفي «المزيد». صفحة الملف تحافظ على بيانات المستخدم وصورته وغلافه، وتعرض المعلومات قبل المنشورات. اللمعان يعيد استخدام حركة الموقع المعتمدة مع احترام تقليل الحركة.

## الأقسام الناقصة

- القرآن: نسخة مولدة من القارئ الموجود و604 ملفات SVG الأصلية وفهرسها والخط ورخصته. يتم التحميل عند فتح القسم، وتعمل روابط الصفحات والفهرس والصوت كما في القارئ الأصلي. مشاركة صفحة أو جزء أو ورد تجهز صورة PNG للصفحة الأولى وروابط الصفحات كلها داخل محرر المنشور الموجود؛ النشر يظل بزر المستخدم.
- الأحاديث: تصدير SQLite المرفقة بعد التحقق من SHA-256، كل الأحاديث الـ14006 في الكتب الأربعة، على دفعات 32 حديثًا. بحث في الكتاب كاملًا من فهرسه عند الطلب، وانتقال برقم الحديث، ومشاركة النص والمرجع في المحرر الموجود.
- الأذكار: تصدير ناتج عن تشغيل AzkarCatalog.kt نفسه باستخدام Kotlin 2.0.21، ست مجموعات، منها 34 للصباح و30 للمساء. عدادات يومية لكل حساب، إعادة وبحث ومشاركة. بناء الموقع يرفض مصدرًا تغير دون إعادة تصديره.
- الرياضة: نفس /api/football والقنوات التي تتيحها الإدارة. عرض المواعيد والنتائج والبحث والتاريخ والمصدر. فيديو HLS يستخدم دعم المتصفح؛ DASH أو صيغة لا يدعمها المتصفح لها رابط المصدر. يوتيوب يستخدم القسم والمشغل الموجودين.
- تسجيلات المؤذنين من الإدارة قابلة للاستماع. الأذان المجدول أثناء إغلاق المتصفح ليس مساويًا لخدمة أندرويد في الخلفية، ولا يدعي هذا التعديل توفيره.

## النشر والتخزين

Wrangler يشغّل scripts/build_web_assets.mjs باستخدام Node >=22.13. الملفات الناتجة من الأصول الأصلية غير مكررة في Git؛ يتم تجهيزها للبناء فقط. الناتج نحو 371 MiB على الخادم، لا ينزل عند فتح الرئيسية: صفحات المصحف والأحاديث تُطلب فقط عند استعمالها. Service Worker يتجاوز هذه الملفات ولا ينسخها كلها إلى ذاكرته. APK لم يتغير حجمه أو إصدارُه.

## التحقق والحدود

نجحت 32 مجموعة اختبارات المشروع القائمة محليًا، واختبار DOM مستقل للتنقل، واستعادة الجلسة، والطلبات، وتطابق كل الأيقونات، والعدادات، والبحث والمشاركة، واكتمال الأحاديث والصفحات. البناء المحلي تحقق من الأصول دون تنزيل محتوى بديل. أضيف الاختبار إلى GitHub Actions باستخدام Node 22.

اختبار DOM لا يقيس شكل العرض بالبكسل أو سرعة هاتف Honor. تعذرت معاينة localhost من المتصفح المتاح (ERR_CONNECTION_REFUSED)، وموقع الإنتاج يطلب تسجيل الدخول؛ لذلك لا توجد مقارنة مرئية مثبتة لكل صفحة مصادق عليها بعد النشر. لا يصح وصف المطابقة البصرية بأنها مضمونة 100% قبل التجربة المرئية على الهاتف. لا يفترض التقرير أن نجاح الدمج يعني أن Cloudflare نشر؛ يجب التحقق من فحص النشر والملفات على الرابط الفعلي.
