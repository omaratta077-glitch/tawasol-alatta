# استقبال تحديثات أرقام القنوات

هذا الجزء يستقبل قائمة جاهزة من أداة تحديث يديرها المالك. لا يجلب المصدر، ولا يفك ترميز ردوده، ولا يشغّل مؤقّتًا.

## الإعداد

أضف Secret باسم `CATALOG_SYNC_KEY` بطول 32 إلى 256 حرفًا إلى Worker العطا الأساسي. عند عدم وجوده، يعيد المسار `503 SYNC_NOT_CONFIGURED` ولا يقرأ القائمة أو يعدّلها.

المسار: `POST /api/internal/football-catalog-sync`.

التوثيق: `Authorization: Bearer <CATALOG_SYNC_KEY>`، ونوع المحتوى `application/json`.

البيانات: `categoryId` كنص موجب حتى 19 رقمًا و`categoryName` بالقيمة `beIN SPORTS (1080P)` (القسم القديم `4` مقبول للتوافق)، و`sourceTime` بقيمة ترويسة `t` ذات العشر خانات من نفس استجابة المصدر، و`entries` قائمة من 1 إلى 40 سجلًا يحوي كل منها `name` و`id` كنص.

حد الطلب 16 كيلوبايت. المفتاح يخص هذا المسار وحده، ولا يمنح صلاحية الحسابات أو الرسائل أو البث.

## الحفظ

تُطابق الأسماء دون حساسية لحالة الأحرف والمسافات، لقنوات المشغّل المسجّلة مسبقًا فقط. الأسماء المتكررة أو الغائبة لا تُختار بالتخمين. لا تُضاف قنوات جديدة، ولا تتغير المباريات أو معرّفات القنوات الثابتة أو حقولها الأخرى. يتم الحفظ في معاملة واحدة داخل قاعدة العطا الحالية. عند عدم تغير الأرقام لا يرتفع إصدار القائمة.

بعد أول حفظ، يتوقف تعديل القناة آليًا إذا غيّر المالك رقمها يدويًا. تُتجاوز القنوات الموقوفة. تُرفض الأرقام المكررة أو غير الصالحة والقوائم الجزئية غير الصالحة، ويبقى آخر حفظ سليم. تُتجاهل الرسائل الأقدم من توقيت آخر استجابة مقبولة.

## حدود هذه المرحلة

إضافة هذا المسار وحدها لا ترسل قائمة من Worker التجربة ولا تفعّل التحديث الدوري. لا توجد قيمة سرية مضمنة في المستودع. اختبار الاتصال بالمصدر وقراءة القنوات نفّذه المالك من حسابه؛ اختبارات الاستقبال محلية وداخل CI باستخدام بيانات مصطنعة.


يدعم القسم المتغيّر: أرسل categoryId كنص موجب حتى 19 رقمًا وcategoryName بالقيمة beIN SPORTS (1080P). يكتشف الناشر القسم بالاسم في كل تجربة حفظ قبل جلب قنواته. يبقى القسم القديم 4 مقبولًا للتوافق فقط. تُحفظ أرقام القنوات كنصوص ولا تُحوّل إلى Number. هذا التعديل لا يفعّل جدولة دورية.


## التجربة من المشروع الأساسي مباشرة

المسار `/api/internal/catalog-check` يعرض نموذج التجربة في العطا نفسه. لا يجلب GET أي بيانات، ولا توجد جدولة دورية. يبدأ الجلب فقط عند إرسال النموذج بمفتاح PROBE_KEY الصحيح؛ خيار الحفظ منفصل وواضح. يستخدم إعداد RESPONSE_MASK من Secrets فقط. يلزم إضافة PROBE_KEY وRESPONSE_MASK إلى مشروع tawasol-alatta، مع إبقاء CATALOG_SYNC_KEY الموجود.

بعد تحديد القسم بالاسم وجلب قنواته، يُرسل الحفظ مباشرة إلى SignalingRoom الحالي عن طريق Durable Object binding. لا توجد مكالمة HTTP عامة إلى Worker آخر أو إلى نفس Worker، ولا يلزم Service binding أو Compatibility flag جديد. تستخدم العملية مسار الاستقبال الحالي ومعاملته الذرية وصلاحيات مفتاح الربط كما هي. عند فشل التحديد أو الجلب لا يُرسل أي حفظ. تتطلب التجربة تهيئة المالك وتشغيله الصريح؛ لا توجد مفاتيح خاصة أو بيانات مصدر حية مضمنة في المستودع.


## التحديث المستقل المستمر

المسار `/api/internal/catalog-update` يعرض صفحة التفعيل في المشروع الأساسي. بعد إضافة أسرار القراءة والمفتاح، يضغط المالك «تفعيل وتحديث الآن» مرة واحدة بمفتاح PROBE_KEY. يبدأ جلب وحفظ فوري ثم يعيد CatalogRefresh جدولة alarm كل نحو 30 ثانية. يظل مستمرًا دون فتح التطبيق أو الصفحة. يوجد زر للحالة وزر لإيقاف التحديث. وقت التنفيذ تقريبي وفق خدمة Cloudflare؛ كل محاولة تكتشف القسم باسمه وتستخدم المعالجة والحفظ الموجودين، دون تنفيذ آخر أو اتصال Worker عام.

الجدولة داخل Durable Object مستقل في نفس المشروع كي لا يتغير alarm إشعارات المنشورات الحالي. تُحفظ حالة التفعيل والنتيجة وموعد المحاولة القادمة. لا يجلب نشر الإصدار أو فتح GET المصدر. عند فشل الجلب أو الحفظ تستمر المحاولة التالية وتبقى القائمة السليمة. التوقف يزيل alarm ويمنع حفظ محاولة جارية قبل تسليمها للاستقبال. لا يضمن تغيير رقم القناة استئناف تشغيل مشغل خارجي شغال بالفعل.


## فحص بيانات تشغيل قناة واحدة

أضيف حقل channel_id الاختياري إلى صفحة catalog-check نفسها. يرسل المالك تجربة يدوية واحدة بمفتاح PROBE_KEY. يقبل معرّفًا نصيًا موجبًا حتى Long.MAX_VALUE، ويطلب فقط المسار الثابت channel/{id}، دون متابعة تحويلات أو إعادة محاولة. لا يقبل الفحص مع حفظ القائمة أو رقم قسم؛ لا يغيّر الجدولة أو الأرقام المحفوظة. يستخدم معالج قراءة الرد الموجود، ويعيد عدد البثوث ووجود الحقول وأنواعها العامة دون قيم URLs أو headers أو DRM أو نص الخادم. لا يحمّل manifest أو مقاطع فيديو أو رخص DRM، ولا يثبت نجاح تشغيل الفيديو. نجاح القراءة بهذا الإعداد يُثبت بالنتيجة فقط؛ لا توجد فرضية أن كل رد تشغيل يستعمل تنسيق القائمة نفسه.
