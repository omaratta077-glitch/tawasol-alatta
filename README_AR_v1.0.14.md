# تواصل العطا — v1.0.14 | الاسم الظاهر + تاريخ الميلاد + شاشة المكالمات

## المطلوب / النتيجة

- **الاسم المعروض:** شاشة المكالمات تجلب `fullName` أو `displayName` من `/api/profile-public` وتعرضه؛ لا تعرض `username` التقني أو معرّفات `g_...` أو Google UID. إن لم يمكن جلب الاسم، يظهر «مستخدم تواصل العطا» بدل المعرف التقني.
- **الاسم عند التسجيل:** صاحب الحساب يكتب الاسم الكامل الذي سيظهر للناس، ويختار معرّفًا فريدًا للحساب بنفسه (`[a-z0-9_]{3,24}`). المعرّف يُستخدم للبحث/الدخول وربط الرسائل دون إظهاره أسفل الاسم في الملف الشخصي أو تحت منشورات التطبيق.
- **تاريخ الميلاد:** حقل تقويم اليوم/الشهر/السنة بدل إدخال رقم العمر، في إنشاء الحساب العادي ومن Google؛ على الموقع وفي أندرويد. الخادم يتحقق من التاريخ الفعلي والعمر المسموح (13–120) ويحسب العمر بنفسه ويحفظ `birthDate` داخل سجل الحساب الخاص فقط. **تاريخ الميلاد لا يدخل الاستجابة العامة `publicUser`**.
- **الحسابات القديمة:** لا تُغيّر أسماؤها أو معرفاتها أو جلساتها أو بياناتها المحفوظة.
- **المكالمات:** شاشة اتصال داكنة ذهبية، صورة/حرف الاسم في الوسط، أيقونات واضحة للميكروفون والكاميرا والسماعة وإنهاء الاتصال. أزرار الاتصال مربوطة بنفس WebRTC السابق، ولا تغيّر خادم المكالمات.

## مهم جدًا: ترتيب التركيب

1. افتح فرع `main` على GitHub، وارفع **مجلد `scripts`** والملف **`.github/workflows/apply-birthdate-v114.yml`** من الحزمة إلى نفس المسارات (لا تضف مجلدًا داخليًا جديدًا).
2. من GitHub Actions شغّل **Apply AL-ATTA Birth Date and Name v1.0.14** على `main`. السكربت يبحث عن نسخة Cloudflare التي سبق تحديثها بإصلاح v1.0.10 ويتوقف بلا تعديلات إذا كانت مختلفة.
3. تأكد أن تعديل `worker.js` و`app.js` و`index.html` **اتنشر بالفعل إلى Cloudflare**، لا تكتفِ بنجاح GitHub Actions. تأكد من ظهور تقويم «تاريخ الميلاد» في إنشاء حساب جديد بالموقع.
4. ارفع **مجلد `android-native`** من الحزمة على فرع `main` مع المحافظة على نفس المسارات.
5. شغّل **Build AL-ATTA Official Release APK**؛ تصدر النسخة `v1.0.14` / `versionCode 114` وتنشر في GitHub Releases بعد نجاح البناء.
6. حدّث التطبيق من داخل التطبيق نفسه (سيطلب أندرويد تأكيد تثبيت APK).

**لماذا يجب نشر Cloudflare أولًا؟** النسخة الجديدة تتحقق من `birthDateSignup:true` في `/api/google-config` ولن تسمح بإنشاء الحساب من التطبيق قبل تحديث الخادم. هذا يمنع إنشاء حساب جديد يختفي تاريخ ميلاده لأن السيرفر القديم لا يحفظه.

## اختبارات عملية بعد التركيب

- حساب جديد ببريد وكلمة مرور: اختيار تاريخ ميلاد من التقويم، ثم كود البريد، ثم عرض الاسم فقط.
- حساب Google جديد: اختيار الحساب، ثم كتابة الاسم الظاهر والمعرّف الخاص وتاريخ الميلاد.
- حساب Google موجود: يدخل مباشرة من غير ما يطلب تاريخ الميلاد من جديد.
- محاولة اسم مستخدم مكرر وتاريخ ميلاد غير منطقي/عمر أقل من 13: الخادم يرفض.
- مكالمة صوتية ومرئية: تظهر صورة واسم الطرف الآخر، لا الرقم الطويل؛ الصوت والفيديو يعملان مع الطرف الآخر.
- اختبار التحديث من التطبيق ومن صفحة Releases.

**التحقق المنجز:** فحص static للملفات و`node --check` للكود والتعديل الآمن على نسخة مرجعية للـCloudflare. لا يوجد اختبار APK أو مكالمة فعلية هنا؛ اختبار GitHub Actions والهاتف مطلوب.
