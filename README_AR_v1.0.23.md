# تواصل العطا — إصلاح Google + YouTube v1.0.23

## النتيجة المقصودة

### أولاً: إنشاء حساب Google
- زر **إنشاء حساب عن طريق Google** لم يعد معطلاً بصمت عندما لم يُحمّل إعداد الخادم وقت فتح التطبيق؛ يجدد `/api/google-config` بعد الضغط ويُظهر رسالة واضحة عند تعذر التفعيل.
- اختيار Google يستخدم Credential Manager الأصلي على أندرويد. يرسل إثبات هوية Google إلى `/api/google-login` ليتحقق الخادم من التوقيع والمصدر والصلاحية وتأكيد البريد.
- **حساب Google موجود**: يفتح الحساب المرتبط مباشرة.
- **حساب جديد**: تظهر شاشة مكتمل فيها البريد والاسم المستردان من Google؛ يختار المستخدم اسم مستخدم ويحدد تاريخ الميلاد (Google ID Token لا يزوّد التطبيق بتاريخ الميلاد). بعدها يضغط **إنشاء الحساب باستخدام Google** وتُنشأ جلسة مباشرة دون إرسال أي كود بريد.
- التسجيل بالبريد/كلمة المرور منفصل وما زال يتطلب رمز التأكيد.
- في حال اختلاف SHA-1 أو Android OAuth أو عدم تفعيل Web Client ID، الخطأ يُعرض للمستخدم. لا يمكن برمجيًا تجاوز إعدادات هوية Google أو تأكيد الخادم.

### ثانيًا: YouTube
- مشغل YouTube التفاعلي IFrame API يعطي أزرار تشغيل/إيقاف وتقديم ±10 ثوانٍ وشريط سحب **عندما يُبلّغ المشغّل عن استعداده**. الأزرار لا تدّعي الوظيفة قبل جاهزية التشغيل.
- إن لم يفتح مشغل IFrame أو أعاد الرمز 153/5، ينتقل التطبيق تلقائيًا إلى مشغل التضمين المباشر. يتذكر وضع المشغل المستعمل محليًا لتسريع التشغيل التالي.
- أزرار واضحة ومستقلة: **تكبير**، **تصغير**، **ملء الشاشة**/عودة. وضع ملء الشاشة يملأ مساحة النافذة المتاحة على الهاتف.
- عند اختيار التشغيل المباشر، يعتمد التقديم الخارجي على أن يتيح WebView عنصر الفيديو؛ وإلا تُستخدم أدوات YouTube الأصلية أو زر «فتح في YouTube». لا يمكن تجاوز منع صاحب الفيديو للتضمين.

## تركيب التصحيح على GitHub
1. خذ محتويات ZIP **التصحيح** وارفعها إلى **جذر مستودع** `omaratta077-glitch/tawasol-alatta` في الفرع `main`، مع الحفاظ على المجلدات `android-native`, `.github`, `scripts`. لا تمسح ملفات الموقع/Cloudflare الموجودة بالمستودع.
2. افتح GitHub **Actions** وشغّل `Apply AL-ATTA Google Signup v1.0.23`. هذه المهمة تفحص مسار Google الحالي للخادم، ثم تضيف العلامة `googleSignupVersion:123` إلى `/api/google-config` إن كان المسار سليمًا. تتوقف بأمان عند غياب دعم التسجيل؛ لا تتجاوز فحصها.
3. **انشر تحديث Cloudflare Worker** بالإجراء المستخدم في مشروعك. مجرد تحديث GitHub لا يعني تحديث الخادم الحي.
4. افتح الرابط `https://tawasol-alatta.omaratta077-4fd.workers.dev/api/google-config` وتحقق من `enabled:true` ووجود `nativeUsernameSignup:true` و`birthDateSignup:true` و`googleSignupVersion:123`. لا تنسخ أسرار Google؛ الـ`clientId` عام.
5. شغّل `Build AL-ATTA Official Release APK` من GitHub Actions. أبقِ **مفتاح توقيع الإصدار الأصلي** لأنه مستخدم في Google OAuth ويتيح تحديث النسخة السابقة دون حذف بيانات المستخدمين.
6. ثبّت APK الإصدار `1.0.23` واختبر بالحسابات: Google جديد، Google موجود، بريد عادي؛ ثم فيديو يسمح بالتضمين وفيديو لا يسمح.

## Google Cloud Console (ضروري إن ظل اختيار الحساب لا يفتح)
- وجود **Web OAuth Client ID** من نفس مشروع Google Cloud المستعمل في `GOOGLE_CLIENT_ID` على Cloudflare.
- وجود **Android OAuth Client** لاسم الحزمة `com.alatta.nativeapp` وبصمة SHA-1 الخاصة **بملف APK الموقع فعليًا**. احتفظ بمفتاح الإصدار ولا تستبدله بمفتاح تصحيح أو مفتاح جديد.
- تحديث Google Play Services على جهاز الاختبار واتصال إنترنت سليم.
- Google ID Token يُرسل للخادم للتحقق، ولا يتم استخدام البريد غير المؤكد لإنشاء حساب.

- لم يتم إنشاء APK موقّع أو تشغيل التطبيق على جهاز أندرويد هنا. لا يمكن إثبات نجاح Google OAuth أو يوتيوب على جهاز محدد دون بناء نسخة وتجربتها.
- لا تحتوي الحزمة على كلمات مرور أو مفاتيح APK أو أسرار Cloudflare.
