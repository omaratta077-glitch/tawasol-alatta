# تواصل العطا — v1.0.12 — النشر الرسمي والتحديث من داخل التطبيق

هذه الحزمة **مصدر Android كامل** مبني على نسخة v1.0.11 المصححة، وتضم تعديلين مترابطين:

1. **نشر إصدار رسمي تلقائيًا:** إجراء `Build AL-ATTA Official Release APK` على فرع `main` يبني APK، يفحص بصمة توقيعه `62:E9:06:55:FD:AF:37:88:70:61:05:CF:4D:99:85:92:CB:BD:82:75`، يرفعه إلى Artifacts، ثم ينشره في GitHub Releases مع ملف SHA256SUMS. لا يُعاد استبدال إصدار منشور مسبقًا.
2. **تحديث من داخل التطبيق:** عند فتح التطبيق يفحص صفحة GitHub Releases، وإذا صدر رقم إصدار أحدث، يظهر تنبيه. الضغط على «تنزيل التحديث» ينزّل APK بواسطة DownloadManager دون فتح Chrome. بعد اكتمال التنزيل، يضغط المستخدم «تثبيت التحديث»، وتعرض نافذة التثبيت الرسمية من Android للتأكيد. إذا طلب Android إذن «التثبيت من هذا المصدر»، يفعّله المستخدم مرة واحدة لتطبيق تواصل العطا.

## كيف تجهّز النسخة v1.0.12

1. افتح مستودع GitHub على **فرع main**.
2. فك الحزمة وارفع **`android-native/`** و **`.github/workflows/build-native-release.yml`** في نفس مساراتها، مع استبدال الملفات القديمة. لا تضعها داخل مجلد آخر.
3. لا ترفع `*.jks` أو كلمات مرور أو أسرار توقيع. أسرار GitHub الموجودة تستمر كما هي.
4. شغّل [Build AL-ATTA Official Release APK](https://github.com/omaratta077-glitch/tawasol-alatta/actions/workflows/build-native-release.yml) من فرع `main`، وتأكد من نجاح آخر خطوة **Publish verified APK to official GitHub Releases**.
5. افتح [صفحة الإصدارات](https://github.com/omaratta077-glitch/tawasol-alatta/releases) على الموبايل ونزّل `tawasol-alatta-v1.0.12.apk`، وثبّته على إصدارك السابق. **هذه أول مرة فقط لتنشيط نظام التحديث الجديد**؛ الإصدارات اللاحقة ستظهر في التطبيق مباشرة بعد نشرها.

## الإصدارات القادمة

- عدّل `versionCode` ليكون رقمًا أعلى من السابق، و`versionName` إلى مثل `1.0.13` في `android-native/app/build.gradle.kts`.
- نفّذ Commit على `main` ثم شغّل إجراء البناء الرسمي.
- بعد ظهور GitHub Release جديد، التطبيق المثبت ذو الإصدار الأقدم يعرض زر تنزيل التحديث داخله عند الفتح.
- لا تغيّر `applicationId=com.alatta.nativeapp`، ولا ملف مفتاح التوقيع، وإلا لن يعمل التثبيت فوق النسخة الحالية.

## قيود وأمان

- تحديثات APK **ليست صامتة**: Android يفرض موافقة المستخدم على التثبيت. الإصدار الموجود على GitHub لا يُثبَّت تلقائيًا دون ضغط المستخدم.
- ميزة `REQUEST_INSTALL_PACKAGES` مناسبة للتوزيع المباشر من GitHub، وقد تخضع لسياسات مختلفة إن نشرت لاحقًا في Google Play.
- النشر يعتمد على صلاحية `contents: write` لـ GitHub Actions. إذا كانت إعدادات المستودع تمنع الكتابة، يجب تمكين صلاحية الكتابة في Settings → Actions → General → Workflow permissions.
- التحقق من SHA-1 يتم قبل نشر APK. يقوم Android بنفسه بالتحقق من مطابقة توقيع APK للتطبيق المثبّت أثناء الترقية.
- إذا كان مستودع GitHub خاصًا، فإن التنزيل المجهول من التطبيق لن يعمل بنفس الطريقة؛ الحزمة مصممة لمستودع Releases عام.
- فُحصت بنية الملفات وXML وYAML وروابط الإصدار ومسار التحديث. **لم أُجر بناء APK حقيقي أو اختبار تثبيت على هاتف من هذه البيئة**؛ GitHub Actions والهاتف هما خطوة التحقق النهائي.
