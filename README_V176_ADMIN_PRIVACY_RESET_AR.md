# تواصل العطا — v1.0.76 / Build 176

## نطاق هذا التحديث
- **لم نلمس محرك مكالمات WebRTC Native أو ملفات عرض القرآن أو مشغّل YouTube.** يظل بطء الاتصال وصفحة القرآن الفارغة مشكلتين مفتوحتين يجب اختبارهُما منفصلتين.
- تم تعديل **التسجيل العادي وبـ Google على الموقع والتطبيق**: النوع إجباري (ذكر/أنثى). عند اختيار أنثى، يظهر سؤال ملزم: إخفاء الحساب نعم/لا. لا يمكن تجاوز هذا الشرط بطلب API مباشر.
- الحساب المخفي لا يظهر في بحث المستخدمين، اقتراحات الأصدقاء، قائمة حضور المتصلين العامة، أو قوائم أصدقاء **الآخرين**، ولا يُفتح ملفه مباشرة لغريب حتى بمعرفة اسمه. يقدر صاحبه يتصفح ويتقدم بطلب صداقة، و**مستلم الطلب** يقدر يطلع على حسابه لقبول الطلب، وبعد القبول يتواصلان. يظهر الحساب في **قائمة أصدقاء المستخدم نفسه** فقط حتى يمكنه التواصل؛ لا يظهر عند استعراض تلك القائمة من حساب آخر.
- التفاعلات التي يمكنها كشف حساب مخفي للغرباء (متابعة/تعليق/إعجاب/مشاركة) محصورة في الأصدقاء، والمجموعات التي يدخلها حساب مخفي تُقيّد بأصدقاء متبادلين. هذا إجراء لمنع تسريب اسم الحساب من الإشعارات العامة.
- صلاحيات الإدارة الحقيقية على الخادم تخص حساب `omar1` **فقط** إذا كان متغير Cloudflare `SUPER_ADMIN_USERNAME` يساوي `omar1` والحساب مُسجّلًا ومالكًا لجلسة صالحة. دور `moderator` القديم لا يمنح صلاحية الإدارة في هذه النسخة.

## معاينة تصفير البيانات — بدون حذف

من حساب المدير `omar1` افتح لوحة الإدارة في الموقع أو التطبيق، ثم اختر **عرض تقرير التصفير**. التقرير يعرض عدد مفاتيح Durable Object وتصنيفها وعدد/حجم الملفات في R2. ليس فيه أي حذف.

### تنزيل نسخة احتياطية فعلية على جهازك

استخدم Python 3 (شخصيًا، **ليس** عبر GitHub Actions أو أي كمبيوتر مشترك)، بعد نشر `cloudflare-site/src/worker.js` الجديد.

من داخل مجلد المشروع شغّل:

```bash
python scripts/owner_backup_preview.py --preview
python scripts/owner_backup_preview.py --backup
```

سيطلب اسم المستخدم `omar1` وكلمة مروره دون عرض كلمة المرور. المخرجات تُحفظ داخل مجلد خاص في مجلد المستخدم المحلي باسم `AL_ATTA_PRIVATE_BACKUP_...`، وتشمل:
- نسخة JSONL من **كل** مفاتيح/قيم Durable Object، ومنها حسابات المستخدمين، المنشورات، الرسائل، علاقات الصداقة، والجلسات.
- ملفات R2 الثنائية (صور/فيديو/صوت)، إن كانت `MEDIA_BUCKET` مهيأة.
- تقرير معاينة وأكواد SHA-256 لكل ملف للتحقق من سلامته.

**تحذير:** هذه النسخة شديدة الحساسية؛ تشمل بيانات شخصية، تجزئات كلمات مرور ورموز جلسات. خزّنها في مساحة مشفّرة وغير مشتركة، ولا ترفعها إلى GitHub أو المحادثة ولا ترسل كلمة المرور أو رمز الجلسة لأحد. السكربت لا يحذف أي بيانات، ولا يرسل النسخة لأي طرف غير Cloudflare الخاص بتطبيقك.

إذا كان حساب المدير **Google فقط بلا كلمة مرور**، فالسكربت الذي يعتمد على كلمة المرور لن يستطيع تسجيل الدخول؛ استخدم معاينة لوحة الإدارة أولًا، ثم نجهز آلية نسخة احتياطية متوافقة مع جلسة Google دون مشاركة رموز المصادقة.

## مراجعة نطاق الحذف — تُعتمد لاحقًا قبل التنفيذ

خطة التصفير المقترحة، **غير منفّذة وغير مفعّلة برمجيًا الآن**:
1. الحفاظ على سجل الحساب `user:omar1` وتسجيله ضمن `usernames`، مع الحفاظ على ارتباط Google الخاص به إذا وُجد. التحقق أولًا من قدرته على إعادة تسجيل الدخول بعد إبطال كل الجلسات.
2. حذف حسابات غير المدير، الجلسات القديمة، مفاتيح Google المرتبطة بحسابات محذوفة، الدعوات المعلقة، المستخدمين والحظر والمتابعات والصداقات والمجموعات والرسائل والمنشورات والقصص والبلاغات والإشعارات وبيانات FCM التابعة للمستخدمين.
3. حصر ملفات R2 بواسطة قائمة الجرد، وتقرير هل نُبقي صورة/غلاف المدير أم نصفر ملفات الوسائط جميعها، بعد النسخ الاحتياطي.
4. **لا** تُمس مفاتيح Cloudflare Secrets، إعدادات Firebase/Google، المستودع، أو التطبيق المنشور.
5. لا تُفعّل عملية الحذف إلا بعد التأكد من اكتمال نسخة Durable Object + R2، ومراجعة التقرير وموافقة منفصلة صريحة على نطاق الحذف.

**مهم:** لا يوجد في النسخة 1.0.76 أي API يحذف القاعدة بالكامل؛ إضافة التنفيذ النهائي تأتي كمرحلة مستقلة بعد مراجعة النسخة والتقرير، منعًا لمسح إنتاجي غير قابل للتراجع.

## التثبيت والنشر

- استخدم ملفات هذا المشروع الكامل على نفس فرع `main` بعد مراجعة الفروق، واحتفظ بـ `.git` الأصلي.
- شغّل `python3 scripts/check_core.py` واختبارات `node scripts/*.mjs` عبر CI، ثم ابنِ وثبّت APK `1.0.76`.
- **انشر Worker المعدل إلى Cloudflare**، وإلا فلن تعمل قواعد الإخفاء أو أدوات معاينة النسخ الاحتياطية الجديدة حتى لو تثبت APK.
- لا تنفذ النسخ الاحتياطية قبل نشر Worker الجديد. وتأكد أن `SUPER_ADMIN_USERNAME=omar1` في بيئة الإنتاج (لا تضع كلمات مرور أو مفاتيح سرية في المستودع).

الاختبارات البرمجية لا تثبت نجاح التطبيق على الهاتف؛ يلزم اختبار فعلي على HONOR بعد بناء APK.
