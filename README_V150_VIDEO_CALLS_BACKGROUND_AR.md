# تواصل العطا v1.0.50 — إصلاحات الفيديو والمكالمات

## ما تم تغييره

- تغيير نافذة المكالمة الواردة إلى الخلفية الداكنة والنص الأبيض والأزرار الذهبية/الداكنة.
- لم يعد محرك الفيديو يعتبر عنصر HTML شغالًا لمجرد أن حدث `playing` حدث؛ ينتظر إطارًا مرسومًا فعليًا. أُزيل فرض `LAYER_TYPE_HARDWARE` على WebView، وأُضيفت محاولة عرض Canvas بالضغط على «عرض الفيديو بطريقة بديلة» عند تعطل سطح الفيديو في Android WebView.
- تظهر رسائل تشخيص أدق عن وصول بايتات الفيديو وفك الإطارات؛ افتح مكالمة الفيديو من الاتجاهين لاختبار الكاميرات والصورة.
- إضافة استلام إشارات المكالمات عند وجود التطبيق بالخلفية باستخدام **Firebase Cloud Messaging (FCM)** عالية الأولوية، وعرض إشعار مكالمة برنين النظام وأزرار رد/رفض. يفتح «رد» التطبيق ثم المكالمة لطلب الأذونات عند الحاجة.
- حفظ رموز أجهزة FCM على حساب المستخدم بعد تسجيل الدخول، وإزالتها بالخادم عند تسجيل الخروج؛ لا تحمل رسائل FCM كلمة المرور أو رمز الجلسة.
- التحسينات السابقة للصوت والرنّ وإظهار «يرن الآن» بعد استلام الدعوة باقية.

## مهم: لا يمكن تفعيل المكالمات بالخلفية بمجرد رفع ملف ZIP!

لا توجد في المستودع المرفق إعدادات Firebase الخاصة بمشروعك أو مفتاح الخادم. لذلك **ستبنى النسخة من دون استقبال FCM** لو رفعتها مباشرةً ولم تجهّز الإعدادات التالية. هذا مقصود حتى لا تُسرب مفاتيح خاصة أو يتوقف البناء.

### 1. إعداد Firebase

1. افتح Firebase Console وأنشئ مشروعًا أو استخدم المشروع الصحيح (يفضّل نفس مشروع Google Cloud للتطبيق إذا كان مناسبًا).
2. سجّل تطبيق Android باسم حزمة `com.alatta.nativeapp` (ليس `.test`).
3. احصل من `google-services.json` على القيم **العامة** التالية (لا تحتاج لرفع الملف نفسه إلى GitHub):
   - `mobilesdk_app_id` ← `ALATTA_FCM_APP_ID`
   - `project_info.project_number` ← `ALATTA_FCM_SENDER_ID`
   - `project_info.project_id` ← `ALATTA_FCM_PROJECT_ID`
   - `client[...].api_key[0].current_key` للتطبيق الصحيح ← `ALATTA_FCM_API_KEY`
4. في المستودع الأساسي GitHub → **Settings → Secrets and variables → Actions → Variables** أنشئ المتغيرات الأربعة السابقة بأسمائها كما هي. قيمها عامة، وليست أسرار توقيع APK.
5. في Google Cloud لنفس المشروع تأكد من تفعيل **Firebase Cloud Messaging API (V1)**، ووفّر حساب خدمة مخوّلًا بإرسال رسائل FCM، وأنشئ مفتاح JSON للاستخدام على الخادم فقط إن لزم.

### 2. إعداد Cloudflare Worker (سر حقيقي)

في Cloudflare Worker **tawasol-alatta** ضع JSON حساب الخدمة في **Secret** باسم:

`FIREBASE_SERVICE_ACCOUNT_JSON`

لا تضع JSON في `wrangler.toml` أو GitHub أو داخل التطبيق، ولا ترسله إلى المحادثة. لا تضعه في متغير عام. يمكن إضافته من Cloudflare Dashboard → Worker → Settings → Variables and Secrets → Add Secret، أو من Wrangler.

إذا كانت هناك قيمة `FIREBASE_PROJECT_ID` للخادم، لازم تطابق `project_id` الموجود في JSON.

### 3. نشر الخادم والبناء

- ارفع تغييرات `cloudflare-site/src/worker.js` إلى Cloudflare (رفع GitHub وحده لا ينشرها بالضرورة): `cd cloudflare-site && npx wrangler deploy` بعد تسجيل الدخول الصحيح.
- بعد إنشاء متغيرات GitHub، ابنِ APK الرسمي من `Actions → Build AL-ATTA Official Release APK`.
- اسم الحزمة بقي رسميًا `com.alatta.nativeapp`؛ يجب الحفاظ على **نفس مفتاح التوقيع الرسمي**.
- على Samsung/Android 13+ اسمح بإشعارات التطبيق، وتأكد من قناة «مكالمات تواصل العطا الواردة»؛ قد تحتاج السماح بالعمل بالخلفية وإلغاء توفير البطارية للتطبيق إذا كانت الإشعارات تتأخر. السماح لا يضمن استقبال مكالمات عند **Force stop** أو أثناء مشاكل الشبكة/سياسات النظام.

### 4. اختبار جهازين

1. من اللابتوب اتصل على هاتف لا يظهر عليه التطبيق في المقدمة، لكن التطبيق مسجّل دخوله. المفروض يظهر إشعار برنين وأزرار رد/رفض خلال مهلة الدعوة (45 ثانية).
2. اضغط «رد» من الإشعار، واسمح بالكاميرا والميكروفون إذا طلبهما النظام.
3. جرّب فيديو من هاتف إلى لابتوب ثم العكس. تحقق من تشغيل الكاميرا بوضوح. لو الشاشة سوداء رغم اتصال الصوت، اضغط زر «عرض الفيديو بطريقة بديلة»؛ إذا بقيت سوداء، صوّر رسالة التشخيص الموضحة على شاشة المكالمة.
4. جرّب «رفض»، وإلغاء المكالمة من اللابتوب، والتأكد من اختفاء الإشعار.
5. جرّب تسجيل الخروج، وتأكد من عدم وصول إشعارات مكالمات خاصة بالحساب السابق.

## الحدود التي لا يمكن ادعاء حلها دون تجربة حقيقية

- لم يُختبر الاتصال الفعلي بين هاتفك واللابتوب هنا، وقد تحتاج شبكة المستخدم إلى إعداد TURN صالح؛ STUN وحده لا يكفي لكل الشبكات.
- Android لا يسمح بإظهار واجهة على القفل عشوائيًا، وقد يحتاج تطبيق الاتصال المؤهل إلى Android Telecom / CallStyle وإذن Full-screen intent وموافقة المتجر أو المستخدم. الإصدار الحالي يرسل **إشعارًا عالي الأولوية** بدل فتح شاشة كاملة بالقوة.
- لا تتوقع رنينًا مضمونًا بعد Force Stop من إعدادات Android، أو عند حظر إشعارات التطبيق؛ هذه قيود نظام وليست أخطاء كود.
- نجاح فحص المصدر/الخادم لا يثبت نجاح بناء APK؛ راجع GitHub Actions وأرسل أخطاء Gradle كاملة إن ظهرت.
