# تواصل العطا — 1.0.68 (Build 168) — إصلاح قبول المكالمة من الخلفية

## المشكلة

قد يصل نفس طلب المكالمة إلى الهاتف بثلاث طرق: Firebase، وWebSocket، وفحص HTTP الدوري. في 1.0.67، كان الضغط على «رد» من إشعار Firebase يفتح المكالمة دون وضع `callId` ضمن المكالمات المعالَجة. عند وصول نسخة متأخرة من `call-request`، قد يرد التطبيق برسالة «busy» على **نفس المكالمة**.

## الإصلاح

- مسار واحد `acceptIncomingInvite` لكل من زر «رد» داخل التطبيق وزر «رد» في إشعار الخلفية.
- تسجيل رقم `callId` قبل فتح محرك الاتصال؛ تجاهل النسخ المكررة القادمة من القنوات الأخرى.
- عدم إرسال «مشغول» إلا عندما تكون هناك *مكالمة مختلفة* قيد التنفيذ.
- منع Firebase من إظهار إشعار جديد لنفس المكالمة بعد قبولها.
- حذف الدعوات التي انتهت مهلتها بعد 45 ثانية حتى لا تبقى حالة «مشغول» معلقة.
- تحديث الإصدار إلى `1.0.68` ورقم البناء `168`، دون تغيير حزمة التطبيق أو التوقيع.

## الملفات المعدلة

- `android-native/app/src/main/java/com/alatta/nativeapp/MainActivity.kt`
- `android-native/app/src/main/java/com/alatta/nativeapp/AttaPush.kt`
- `android-native/app/build.gradle.kts`
- `scripts/check_core.py`

**لم تتغير ملفات YouTube أو WebRTC أو الموقع/Cloudflare أو تسجيل Google.** إصلاح `FCM_HTTP_400` من النسخة 1.0.67 محفوظ كما هو.

## الرفع من اللابتوب

1. حدّث مستودع GitHub Desktop إلى نفس الفرع الذي تعمل عليه. لا تنسخ هذا التعديل فوق ملف `MainActivity.kt` أحدث غير مفحوص.
2. يفضل فك **ملف التعديل فقط**، ونسخ الملفات الأربعة إلى المسارات نفسها داخل المستودع.
3. راجع `Changes`، ثم Commit وPush للفرع المعتمد.
4. شغّل `Build AL-ATTA Official Release APK` على **نفس الفرع**؛ تأكد أنه يعرض 1.0.68.
5. جرّب على HONOR: شاشة مقفلة، اتصال من حساب آخر، «رد» من إشعار الخلفية، ثم إنهاء الاتصال، ثم اتصال ثانٍ. يجب ألا تصل رسالة «مشغول» لنفس المكالمة.

## ما تم اختباره وما لم يُختبر

اجتازت ملفات المصدر فحص `check_core.py` واختبارات Node الخاصة بالإشارات والإشعارات والمكالمات، مع فحص ثابت جديد للتكرار وقفل المكالمة. لم تتوفر هنا بيئة Android SDK/Gradle كاملة؛ لذلك **لم يُبنَ APK ولم يُختبر استقبال اتصال حقيقي على هاتف HONOR**.

هذا الإصلاح لا يتطلب إعادة إضافة مفاتيح Firebase أو إعادة نشر Cloudflare ما دام إصلاح النسخة 1.0.67 منشورًا ويصل الإشعار التجريبي فعلًا.
