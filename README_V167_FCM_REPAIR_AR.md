# تواصل العطا — إصلاح فشل إرسال إشعارات Firebase (1.0.67)

## السبب
استعمل Cloudflare Worker المفتاح `from` داخل `message.data` عند إرسال رسائل FCM. الاسم `from` محجوز في Firebase، وبالتالي يُرفض الطلب غالبًا بـ HTTP 400. لم يكن ضبط صلاحية الإشعارات على HONOR كافيًا لتجاوز هذا الرفض.

## التغيير
- `cloudflare-site/src/worker.js`: إعادة تسمية `from` إلى `sender` **في نسخة البيانات المرسلة إلى Firebase فقط**، دون تغيير بيانات المكالمات أو الدردشة الموجودة في الخادم. سجل رفض FCM يعرض رمز الحالة والحقل غير الصالح فقط دون مفاتيح أو رموز الأجهزة.
- `android-native/app/src/main/java/com/alatta/nativeapp/AttaPush.kt`: قراءة `sender` مع دعم الاسم السابق `from` للتوافق.
- `android-native/app/build.gradle.kts`: إصدار 1.0.67 / البناء 167.
- `scripts/check_core.py` و` scripts/test_fcm_reserved_key.mjs`: فحص لمنع عودة الاسم المحجوز في إشعارات المكالمة والرسالة والتجربة.

## خطوات النشر
1. هذه الملفات مبنية على مصدر النسخة 1.0.66. قارنها بآخر نسخة لديك قبل استبدالها، خصوصًا إن كان `main` يحتوي على تعديلات أحدث. لا تنسخ مشروعًا قديمًا كاملًا فوقه.
2. بعد تحديث `worker.js` في المستودع، انشر Cloudflare Worker من مجلد `cloudflare-site` بالطريقة الرسمية لمشروعك (Wrangler)، ولا تكتفِ بعمل Push على GitHub.
3. بعد نشر Worker، جرّب من التطبيق «إرسال إشعار تجريبي لجهازي». يجب أن تختفي رسالة `FCM_HTTP_400` إذا كان هذا هو السبب الوحيد.
4. بعد نجاح اختبار الإشعار، ابنِ وثبّت Android APK 1.0.67 ليقرأ المفتاح `sender` في **مكالمات الخلفية**. الخادم الجديد مع APK القديم قد يقبل إرسال المكالمة لكنه لا يُظهرها لأن التطبيق القديم لا يقرأ اسم المرسل الجديد.
5. إذا استمر الرفض، راجع `Observability` في Cloudflare بحثًا عن `FCM delivery rejected` وشارك HTTP/status والحقل فقط (بدون Token أو مفاتيح).
6. بعد وصول إشعار الاختبار اختبر مكالمة والهاتف مقفولًا، مع مراعاة أذونات الإشعارات وإدارة بطارية HONOR. إرسال FCM المقبول لا يضمن وصوله أو الرنين في جميع أوضاع إغلاق التطبيق أو إيقافه قسريًا.

## ما الذي لم يتغيّر؟
ملفات يوتيوب وكود WebRTC وGoogle OAuth وكلمات المرور والتوقيع الرسمي وCloudflare secrets لم تُعدّل.
